Measured 2026-11-01T18:54Z..19:04Z on the build host, read-only, while run N built.

Why this file exists
--------------------
§10's M1 exit criterion has two halves:

    Exit: `dpkg -l` from the built image diffed against §5 comes back empty, in both
    directions.   ...  §5 inventory complete with a justification per entry.

The first half went green on run M (logs/M1-diff-runM.txt:86, "M1 EXIT CRITERION: MET").
The second half had never been run as a check against §5's *text*. The reason it could go
unnoticed is in scripts/m1-diff.sh:37, which states the bridge the diff relies on:

    manifests/base.pkgs, manifests/desktop.pkgs  — §5's inventory. This is what the exit
          criterion actually means.

The diff compares manifest against image, and then trusts that sentence. A name in a
manifest that §5 does not contain is invisible to both directions: direction 1 finds it
installed, direction 2 finds it expected. So the only way to test the bridge is to read
§5 and test every manifest name against it. That was done, and it found one name with no
§5 basis. This file settles whether that name is load-bearing — must be justified in §5 —
or decorative — must come out of the manifest.

4. What this does not claim
---------------------------
  * **No build was run with the line removed.** The conclusion is from the archive's
    dependency edges and from the metapackage's generated Depends, both read out of files,
    not from an experiment. A build with `xorg` dropped would be the direct test and has not
    been done; it is also not cheap — §9.1 puts a run at ~1 h 45 m.
  * The claim is about *this* selection. `task-desktop` is a real alternative route: it
    Depends on `xorg, xserver-xorg-video-all, xserver-xorg-input-all, desktop-base` and
    `tasksel (= 3.81)`. §5 does not name it, and naming it would mean taking tasksel and
    desktop-base and letting a Debian task choose the session — which is the "default
    install with a new name" §5's inventory tail exists to refuse.
  * `xorg` is not the only possible X-server name. `xserver-xorg` alone would give the
    server plus driver metapackages without xorg's fonts, x11-apps, x11-utils or xinit;
    `xserver-xorg-core` alone would give the Xorg binary with **no** input or video driver,
    since those come in through `xserver-xorg`'s Depends. `xorg` is the name that matches
    what §5's session actually needs and what `xfce4`'s own Recommends would have chosen.
  * Whether X11 rather than Wayland is right is not decided here. §7.2:458 already records
    the session is X11 ("built for X11, which matches our lightdm + Xfce session"), and
    lightdm + Xfce 4.20 on trixie has no Wayland session to name. This file only establishes
    that the X server the spec already assumes is a package §5 has to name.
