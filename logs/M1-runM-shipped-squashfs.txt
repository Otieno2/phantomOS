A correction to how the timestamp above reads, added 2026-11-01T18:25Z after the measurement in
logs/M1-buildid-per-run.txt: that mtime is **not** when the build wrote the ISO. live-build's
binary_iso:230 does `touch -d@${SOURCE_DATE_EPOCH} ${IMAGE}`, so the artifact's mtime is the
epoch, which is the wall-clock second live-build read its configuration — one second after
build-iso.sh stamped the run. Run M's record says `run: 2026-11-01T140727Z ..
2026-11-01T155206Z` and its log ends `[2026-11-01 18:52:04] lb source` / `P: Build completed
successfully`, so the run took 1 h 44 m 39 s while this file's mtime says 17:07:28 +0300 =
14:07:28Z. Same for the squashfs "Creation or last append time" below, which binary:74's
unconditional `find … -exec touch -d@${SOURCE_DATE_EPOCH}` rewinds the same way. Nothing quoted
from an mtime in this file is a finish time; the finish time is in
logs/M1-artifact-2026-11-01T140727Z.txt's `run: … .. …` line.

=== what this file cannot show, and why ===
The comparison's other half is gone. `m1-diff.sh` reads
`$WORK/live/binary/live/filesystem.squashfs`, and the cold-clean that run N started from (SPEC
§9.1's procedure: delete `live/.build`, `live/chroot*`, `live/binary`, `live/tmp`, `live/.lock`,
`live/cache/bootstrap`) removed `live/binary` wholesale. Verified absent at 17:24Z:

  ls: cannot access '/root/phantomos-m1/live/binary/live/filesystem.squashfs': No such file or directory

So "the build tree's copy had the same sha256" is a claim about a file that no longer exists and
cannot be re-measured for run M. Two things keep it from being load-bearing on its own:

  1. live-build does not rewrite the squashfs between `binary_rootfs` and `binary_iso` — it copies
     it into the ISO image tree (`binary_chroot`/`binary_rootfs` write `binary/live/`, `binary_iso`
     wraps it). The earlier build whose evidence *was* archived shows the identity directly:
     logs/M1-shipped-squashfs.txt:107-109 has the same sha256 for `/mnt/m1iso/live/filesystem.squashfs`
     and `/root/phantomos-m1/live/binary/live/filesystem.squashfs` (f2f7d1ee…, that build's value).
     That is a different build, so it is evidence about the mechanism, not about run M's bytes.
  2. `m1-diff.sh`'s own output for run M agrees with what the ISO contains on every number that can
     be checked from outside: 834 installed packages, 47 705 paths, and the six shipped channels
     (logs/M1-diff-runM.txt:2, :74-80).
